§1INTRODUCTION — THE REV F MODEL

Realms, homing, callsigns

1.1 Distinct WAN realms. Each MANET constitutes its own WAN address realm: radios in MANET A carry HW-derived /32s from 172.20.0.0/16, radios in MANET B from 172.21.0.0/16. Consequences: (a) inter-mesh address collisions are impossible by plan (the Rev E shadow-alias machinery is demoted to a misprovisioning safeguard, §8.4); (b) the realm prefix is the routing decision — any router can classify a destination as "my mesh / other mesh / external" by prefix alone, with zero protocol exchange.

1.2 Homing. A platform carries one radio (single-homed, member of one realm) or two (dual-homed, one radio per realm, joined by its internal platform link). Every dual-homed platform is structurally a gateway — RR-A⇄RR-B forwarding across its platform link — whether or not it also hosts DNS or reach-back. Multiple dual-homed platforms may exist simultaneously; §3.3 and UC-6 define how single-homed platforms select among them and why transit is loop-free.

1.3 Callsigns. Each platform owns a static callsign (viper1, rhino7, …) which is its DNS name in the flat zone tac.. The callsign↔addresses map is static provisioning (both are fixed properties of the hardware); what stays dynamic is which of a platform's addresses is currently reachable — and therefore which one DNS answers with (§6). A dual-homed platform has one name and up to two answers, chosen realm-aware.

What survives from Rev E unchanged Radio-embedded routers; app LANs behind every RR with GW = DNS = router IP (one DHCP option set); edge PAT onto the radio /32; injector damping; OSPF only on platform links; QoS at every radio egress; all latency physics.

Loop-freedom by construction: realms are disjoint, every inter-realm packet crosses exactly one platform link (the first gateway it reaches), and on the far side the destination is on-link — there is no rule under which a second gateway is ever consulted for the same packet. OSPF runs independently inside each dual platform (between its own RR pair) purely so each sibling learns the other realm's live /32 set; the two gateways' OSPF processes never peer with each other, and don't need to.

§9COST SHARING

Gateway scoring, radio metrics into routing, the air budget

9.1 Gateway selection (IF-9) — metrics the radio already paid for

Each single-homed RR holds the provisioned gateway table {RHINO7: prio 100, BADGER2: prio 80, …}. Every 30 s (damped, hysteresis 20 %), it scores the candidates that currently appear in its member list:

score(GW) = priority
           + w1 · normalized(link_quality to GW)     ! from radio MAC (IF-1)
           − w2 · hop_estimate(GW)                   ! if the MAC exposes path length
switch only if best ≥ current · 1.2                  ! hysteresis — no oscillation

The same radio-measured link metrics also drive OSPF mesh-interface cost inside each dual platform (IF-8, damped 30 s) so a dual platform with a degrading radio becomes less attractive in BOTH mechanisms at once — without one byte of signalling: the cost information is shared from the MAC layer outward, free, because the router lives inside the radio.

§13DESIGN RULES

Twelve rules that define this system

  1. No routing protocol on any mesh interface — OSPF lives only inside dual platforms, on their own platform links.
  2. The radio MAC layer is the single source of truth for membership, names' answerability, link costs, and gateway liveness.
  3. One realm per MANET; the prefix is the routing decision. 172.20/16 ⇒ mesh A, 172.21/16 ⇒ mesh B, else external.
  4. The radio /32 is the platform's transit identity; app LANs hide behind edge PAT, services are callsign + port.
  5. On dual platforms, PAT source = egress-realm /32 so replies route home without double transit.
  6. Any dual-homed platform is a gateway; transit crosses exactly one platform link, far side always on-link — loop-free by construction.
  7. Gateway selection is local, scored, damped: provisioned priorities × radio metrics, 20 % hysteresis, zero signalling.
  8. Callsigns are static identity; the zone is provisioning data; answers are realm-aware and reachability-gated (resolvable ⇔ routable).
  9. Apps configure one thing: GW = DNS = their router's LAN IP.
  10. Damp, then act — routes, records, gateway switches, OSPF costs: every reaction waits out the radio's noise.
  11. NAT timeouts are air policy: UDP 600 s, TCP 3600 s, EIM/EIF, hairpin on.
  12. Serialization is the latency: UDP-first, MSS 512, PDUs ≤ ~250 B, caches load-bearing; budget 35/15/50 at every radio egress.
Net result Any app, behind any platform, reaches any callsign — the realm rule routes it, the nearest healthy dual platform relays it, DNS answers with the right face of the right radio, and the only things the air ever carries are application data and a budgeted trickle of name lookups.
